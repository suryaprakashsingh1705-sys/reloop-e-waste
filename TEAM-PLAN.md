# Team plan — 3 people

## Workstream A — Product & demo (team lead)
- Confirm the single user journey and keep the pitch aligned with the working build.
- Verify official local e-waste collection information; record the source and date checked.
- Prepare the three-minute screen recording and final submission text.

## Workstream B — Frontend & QA
- Test add/search/filter/status/export on desktop and mobile-sized viewports.
- Test refresh persistence, empty states, invalid form entries, and status confirmation.
- Remove or label all demo records before judging so they cannot be mistaken for real impact.

## Workstream C — AWS & evidence
- Deploy the static app to AWS Amplify Hosting using an authorized team member's AWS account.
- Verify the public URL in a private/incognito browser and on a phone.
- Capture proof of the running deployment and ensure no secrets are committed.
- If deploying is blocked, investigate one qualifying AWS open-source tool; document and demonstrate actual usage, not just a mention in the README.

## Submission gates
- [ ] One main flow works from start to finish
- [ ] Verified local recycling information or an explicit limitation is shown
- [ ] No false claims about AI, pickup bookings, verified recovery, or impact
- [ ] AWS eligibility route is implemented and tested
- [ ] Public URL (if deployed) works without login
- [ ] Three-minute demo video recorded and reviewed
- [ ] Team reviews final submission before submitting
